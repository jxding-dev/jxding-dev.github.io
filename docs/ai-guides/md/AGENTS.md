# AGENTS.md

앞으로 모든 웹사이트, 웹앱, UI/UX 데모 작업에 적용할 기준이다.  
사용자가 **취미 프로젝트**라고 명시하지 않으면 기본적으로 **판매용 프로젝트**로 간주한다.

## 핵심 원칙

- 토큰은 아끼되 결과물 완성도는 낮추지 않는다.
- 설명은 짧게, 작업은 바로 한다.
- 프로젝트마다 고유한 개성과 분위기를 만든다.
- 업종명만 바꾼 템플릿형 디자인을 반복하지 않는다.
- 최신 UI/UX 흐름을 참고하되 그대로 복사하지 않는다.
- 예쁘기만 한 화면보다 실제 사용하기 쉬운 화면을 만든다.
- 구매자에게 바로 전달해도 되는 수준의 완성도와 안정성을 목표로 한다.
- 오류, 버그, 콘솔 에러, 깨진 링크, 작동하지 않는 버튼을 최소화한다.

## 디자인 기준

- 프로젝트 성격에 맞는 시각 언어를 먼저 정한다.
- 카드 나열, 흔한 히어로, 의미 없는 그라데이션, 장식용 blur/shadow 남발을 피한다.
- 화면은 세련되고 동적이어야 하며 hover, focus, active, disabled, transition 상태를 챙긴다.
- 애니메이션은 과하지 않게 쓰고 사용성을 해치지 않는다.
- 버튼, 탭, 폼, 모달, 토스트, 필터, 검색 등 실제 사용 흐름을 고려한다.
- 문구는 추상적인 홍보문보다 실제 기능과 사용자 행동에 연결되게 쓴다.

## 레이아웃과 간격

- 박스, 인라인, 블록, 텍스트 사이 간격을 꼼꼼히 맞춘다.
- 카드 padding, 버튼 gap, 제목/본문/버튼 간격, 아이콘/텍스트 간격을 정리한다.
- 텍스트, 버튼, 배지, 이미지가 부모 영역 밖으로 튀면 안 된다.
- 요소가 겹치거나 밀리거나 잘리면 안 된다.
- `overflow-x: hidden`으로 문제를 덮지 말고 원인을 수정한다.
- grid는 `minmax(0, 1fr)`, flex item은 필요 시 `min-width: 0`을 사용한다.
- 큰 화면에서 콘텐츠가 끝없이 퍼지지 않도록 `max-width`, column, side panel을 설계한다.

## 반응형 기준

최소 너비는 **360px**이다. 모바일만 보지 말고 큰 모니터까지 확인한다.

확인 기준:

- `360px`
- `390px`
- `480px`
- `768px`
- `1024px`
- `1280px`
- `1440px`
- `1920px 이상`

각 화면에서 가로 스크롤, 텍스트 튐, 버튼 잘림, fixed 요소 겹침, modal/dropdown 이탈이 없어야 한다.

## 코드 기준

- 유지보수 가능한 구조를 우선한다.
- 스파게티 코드, 클래스 남발, 중복 CSS/JS를 피한다.
- 클래스는 의미와 역할이 분명할 때만 추가한다.
- `.box1`, `.item`, `.left`, `.right`, `.temp` 같은 의미 없는 이름을 피한다.
- HTML, CSS, JS 역할을 분리한다.
- 공통 스타일은 재사용하고 일회성 하드코딩을 줄인다.
- 사용하지 않는 class, 빈 selector, 죽은 JS 함수, `console.log`를 남기지 않는다.
- 사용자가 요청하지 않은 외부 라이브러리를 추가하지 않는다.
- HTML에는 한글 깨짐 방지를 위해 `<meta charset="UTF-8">`를 유지한다.

## JS 기준

- Vanilla JS 중심으로 작성한다.
- 모든 JS는 `DOMContentLoaded` 이후 실행한다.
- 해당 DOM이 없으면 조용히 종료한다.
- `querySelector` 결과가 null일 수 있음을 고려한다.
- 이벤트 중복 등록을 피한다.
- LocalStorage key는 프로젝트명 prefix를 붙인다.
- 서버 통신이 필요한 기능은 실제 전송하지 않고 프론트 데모임을 명시한다.

## 접근성과 상태

- 클릭 가능한 요소는 가능한 `button` 또는 `a`를 사용한다.
- form에는 label을 연결한다.
- hover뿐 아니라 focus 상태도 제공한다.
- disabled 상태를 명확히 표현한다.
- 색만으로 상태를 구분하지 말고 텍스트도 함께 제공한다.
- modal은 닫기, 취소, 저장 역할이 분명해야 한다.

## 판매용 품질

취미 프로젝트라고 명시되지 않은 작업은 다음 기준을 만족해야 한다.

- 주요 사용자 흐름이 끊기지 않는다.
- 콘솔 오류가 없다.
- 링크, 버튼, 폼, 메뉴, 모달이 정상 작동한다.
- 빈 상태, 오류 상태, 로딩 상태가 필요한 곳은 방치하지 않는다.
- 더미 데이터와 문구도 실제 서비스처럼 자연스럽다.
- 구매자가 텍스트, 이미지, 색상, 데이터를 쉽게 수정할 수 있다.
- README에는 실행 방법, 페이지 구성, 주요 기능, 수정 위치를 정리한다.

## 최종 확인

작업 후 최소한 다음을 확인한다.

- [ ] 레이아웃이 360px부터 1920px 이상까지 깨지지 않는다.
- [ ] 텍스트, 버튼, 배지, 이미지가 튀거나 겹치지 않는다.
- [ ] 간격과 padding이 어색하지 않다.
- [ ] hover/focus/active/disabled 상태가 있다.
- [ ] 주요 기능에서 JS 오류가 없다.
- [ ] 불필요한 class, 중복 CSS/JS, 죽은 코드가 없다.
- [ ] 프로젝트 주제와 맞지 않는 이전 문구가 남아 있지 않다.
- [ ] 판매용으로 바로 전달해도 어색하지 않은 완성도다.
