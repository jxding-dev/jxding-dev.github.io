# LANDING_GUIDE.md

이 문서는 판매용 랜딩페이지 목업을 설계할 때 사용하는 UX 흐름과 섹션 구성 기준입니다.

랜딩페이지의 목표는 단순히 예쁜 화면이 아니라, 방문자가 서비스를 이해하고 자연스럽게 행동하도록 만드는 것입니다.

---

## 1. 랜딩페이지 핵심 목적

랜딩페이지는 다음 질문에 빠르게 답해야 합니다.

```text
1. 여기는 무엇을 제공하는가?
2. 나에게 왜 필요한가?
3. 다른 곳보다 무엇이 좋은가?
4. 실제로 믿을 만한가?
5. 지금 무엇을 하면 되는가?
```

## 4. Hero 설계 원칙

Hero는 첫 3초 안에 페이지 목적을 전달해야 합니다.

Hero 필수 요소:

- 명확한 제목
- 짧은 보조 설명
- 핵심 CTA
- 보조 CTA
- 신뢰 요소 또는 시각 이미지

좋은 Hero 제목:

```text
감성은 살리고, 예약은 쉽게 만드는 작은 카페 홈페이지
피부 고민을 차분히 상담하는 1:1 맞춤 관리 공간
동네 업체도 전문적으로 보이게 만드는 반응형 소개 페이지
```

나쁜 Hero 제목:

```text
최고의 서비스를 제공합니다
당신의 성공 파트너
새로운 경험을 만나보세요
```

문제가 되는 이유:

- 구체성이 없음
- 업종이 안 보임
- 사용자가 얻는 결과가 불명확함

## 5. 문제 제시 섹션

사용자가 가진 고민을 짧고 구체적으로 보여줍니다.

예시:

```text
가격표는 있는데 예약 문의가 잘 안 들어오나요?
인스타그램만으로는 매장 정보를 설명하기 부족한가요?
방문 전 고객이 위치와 메뉴를 찾기 어렵나요?
```

규칙:

- 너무 부정적으로 몰아가지 않습니다.
- 사용자가 실제로 겪을 만한 문제만 씁니다.
- 3개 이하로 정리합니다.

---

## 6. 해결 방법 섹션

문제 다음에는 바로 해결 구조를 보여줍니다.

예시:

```text
메뉴, 위치, 예약, 후기를 한 페이지에서 자연스럽게 확인할 수 있도록 구성합니다.
```

구성:

- 핵심 해결 문장
- 해결 포인트 3개
- 시각적 카드 또는 아이콘

---

## 7. 서비스 / 기능 섹션

서비스를 나열할 때는 단순 기능이 아니라 고객이 얻는 결과로 설명합니다.

나쁜 예:

```text
반응형 제작
이미지 교체
버튼 추가
```

좋은 예:

```text
모바일에서도 메뉴와 예약 버튼이 바로 보이도록 구성
고객이 궁금해하는 가격과 위치를 한눈에 정리
후기와 사진을 자연스럽게 배치해 신뢰감 강화
```

---

## 8. 프로세스 섹션

프로세스는 고객 불안을 줄이는 역할입니다.

기본 구조:

```text
1. 문의
2. 자료 전달
3. 초안 제작
4. 수정
5. 최종 전달
```

업종별로 바꿔서 사용합니다.

예시:

카페:

```text
매장 분위기 확인
대표 메뉴 정리
페이지 초안 제작
모바일 화면 조정
최종 배포
```

뷰티샵:

```text
시술 항목 정리
가격표 구성
포트폴리오 이미지 배치
예약 버튼 연결
최종 확인
```

---

## 9. 포트폴리오 / 갤러리 섹션

갤러리는 단순 이미지 나열이 아니라 분위기를 전달해야 합니다.

구성 방식:

- 3열 카드
- Bento Grid
- Before / After
- 가로 스크롤 갤러리
- 대표 이미지 + 작은 이미지 조합

주의:

- 이미지 비율을 통일합니다.
- 모바일에서 이미지가 너무 작아지지 않게 합니다.
- 캡션이 있으면 짧게 작성합니다.

---

## 10. 후기 섹션

후기는 신뢰 요소입니다.

후기 카드 구성:

- 이름 또는 익명 표기
- 짧은 후기
- 서비스/구매 항목
- 별점은 선택

좋은 후기 문장:

```text
메뉴와 위치가 한눈에 보여서 문의가 훨씬 쉬워졌어요.
모바일에서 예약 버튼이 잘 보여서 고객 안내가 편해졌습니다.
```

주의:

- 너무 과장된 후기는 피합니다.
- 모든 후기가 비슷한 말투가 되지 않게 합니다.

---

## 11. FAQ 섹션

FAQ는 전환 직전의 불안을 줄입니다.

자주 넣을 질문:

```text
제작 기간은 얼마나 걸리나요?
자료는 무엇을 준비해야 하나요?
수정은 몇 번 가능한가요?
도메인과 호스팅은 어떻게 하나요?
모바일에서도 잘 보이나요?
추후 수정도 가능한가요?
```

FAQ는 accordion 형태를 기본으로 사용합니다.

## 12. CTA 섹션

CTA는 페이지 전체에서 반복되지만, 너무 과하면 부담스럽습니다.

CTA 위치:

- Hero
- 중간 섹션 후
- 마지막 Contact 전
- Footer 근처

CTA 문구 예시:

```text
상담 문의하기
예약하기
가격표 보기
메뉴 확인하기
견적 요청하기
오시는 길 보기
카카오톡 문의하기
```

나쁜 CTA:

```text
Click Here
Submit
More
Start
```

## 13. Contact 섹션

Contact 섹션 필수 요소:

- 전화번호
- 카카오톡 또는 SNS 링크
- 주소
- 영업시간
- 지도 영역
- 문의 폼 또는 외부 폼 링크

백엔드가 없는 정적 사이트에서는 다음 방식을 사용합니다.

- 카카오톡 채널 링크
- 네이버 예약 링크
- 구글폼 링크
- 전화 링크
- 이메일 링크
- 인스타그램 DM 안내

폼을 넣을 경우 실제 저장 기능이 없으면 명확히 처리합니다.

## 14. 문구 작성 규칙

문구는 짧고 구체적으로 작성합니다.

### 제목

- 1줄 또는 2줄
- 무엇을 제공하는지 명확하게
- 추상어 남발 금지

### 본문

- 2~3문장 이하
- 긴 설명보다 핵심 정보 우선
- 모바일에서 읽기 쉽게 줄임

### 버튼

- 행동을 명확히 표현
- 2~5단어 정도
- 현재 위치에서 가장 자연스러운 행동

## 15. 랜딩페이지 금지 문구

아래 표현은 너무 흔하거나 신뢰가 낮습니다.

```text
최고의 서비스
완벽한 솔루션
차원이 다른 경험
고객 만족 100%
무조건 효과
업계 최고
성공을 약속합니다
```

대신 구체적으로 씁니다.

```text
메뉴, 위치, 예약 정보를 한 화면에 정리합니다.
처음 방문한 고객도 가격과 과정을 쉽게 이해할 수 있게 구성합니다.
모바일에서 바로 문의할 수 있도록 CTA를 고정 배치합니다.
```

## 16. 랜딩페이지 Self Check

작업 완료 후 확인합니다.

```text
□ 첫 화면에서 무엇을 제공하는지 바로 알 수 있는가?
□ CTA가 명확한가?
□ 섹션 순서가 자연스러운가?
□ 비슷한 목적의 섹션이 반복되지 않는가?
□ 사용자의 불안을 줄이는 정보가 있는가?
□ 후기, 과정, FAQ 중 최소 하나의 신뢰 요소가 있는가?
□ 모바일에서 CTA가 잘 보이는가?
□ 문의 또는 예약으로 이어지는 경로가 명확한가?
□ 문구가 너무 추상적이지 않은가?
□ 실제 업체가 써도 어색하지 않은가?
```
