# AGENTS.md

이 문서는 Codex가 프로젝트를 수정하거나 새 랜딩페이지 목업을 제작할 때 항상 따르는 최상위 작업 기준입니다.

자세한 디자인 규칙은 필요할 때만 아래 문서를 참고합니다.

- `DESIGN_SYSTEM.md`: 색상, 폰트, 여백, radius, shadow, 공통 컴포넌트 기준
- `LANDING_GUIDE.md`: 랜딩페이지 설계 흐름, 섹션 구성, CTA 구조
- `COMPONENT_LIBRARY.md`: Hero, Card, Button, FAQ, Review 등 컴포넌트 패턴

---

## 1. 가장 중요한 원칙

- 디자인 품질이 우선입니다.
- 단, 유지보수성을 해치지 않습니다.
- 새 프로젝트는 기존 프로젝트와 다른 새로운 디자인을 목표로 합니다.
- 코드를 작성하기 전에 먼저 디자인 시스템을 설계합니다.
- 기존에 생성했던 Hero, Card, Button, Footer, Navigation을 그대로 반복하지 않습니다.
- 색상만 바꾸거나 이미지만 교체한 것은 새로운 디자인으로 인정하지 않습니다.

---

## 2. 작업 목표

판매용 홈페이지 목업 템플릿을 제작하거나 기존 랜딩페이지를 수정합니다.

결과물은 AI가 만든 티가 나는 단순 템플릿이 아니라, 실제 소규모 업체가 사용할 수 있는 완성도 있는 반응형 웹사이트처럼 보여야 합니다.

제작 예시 업종:

- 감성 카페
- 디저트샵
- 피부관리샵
- 미용실
- 네일샵
- 병원/클리닉
- 클래스/강사
- 공방/스튜디오
- 소규모 업체 소개
- 포트폴리오
- 로컬 서비스 업체

---

## 3. 최우선 작업 규칙

- 기존 화면, 기능, 반응형을 깨지 않습니다.
- 요청과 직접 관련된 파일만 최소 수정합니다.
- 애매하면 새로 만들지 말고 기존 구조를 유지합니다.
- 이전 AI의 작업을 먼저 읽고 이어서 수정합니다.
- 수정 전 유지해야 할 화면, 기능, 반응형 범위를 확인합니다.
- 버튼, 링크, 폼, 탭, 토글, 스크롤 이벤트를 건드리는지 확인합니다.
- 클래스명 변경 시 HTML, CSS, JS 참조를 함께 확인합니다.
- 삭제 전 실제 사용 여부를 확인합니다.

---

## 4. 토큰 절약 규칙

- 처음부터 모든 파일을 읽지 않습니다.
- 관련 파일만 찾고 필요한 부분만 확인합니다.
- 긴 파일은 전체 출력보다 검색, 파일 목록, 필요한 범위 읽기를 우선합니다.
- 답변은 짧게 씁니다.
- 수정 파일, 핵심 변경, 확인 결과만 남깁니다.
- 설명보다 작업 결과를 우선합니다.
- 중복 규칙 문서를 새로 만들지 않습니다.
- 같은 내용을 반복하지 않습니다.
- UI 세부값이 필요할 때만 관련 문서를 읽습니다.

문서 참고 기준:

- 레이아웃, 색상, 폰트, 여백, radius, shadow가 필요하면 `DESIGN_SYSTEM.md`
- 랜딩페이지 흐름, 섹션 순서, CTA 설계가 필요하면 `LANDING_GUIDE.md`
- Hero, Card, FAQ, Review, Button 패턴이 필요하면 `COMPONENT_LIBRARY.md`

## 5. 기본 파일 구조

새 목업을 제작할 때는 아래 구조를 기본으로 사용합니다.

```text
project/
├─ index.html
├─ pages/
│  ├─ about.html
│  ├─ service.html
│  ├─ review.html
│  └─ contact.html
├─ css/
│  ├─ reset.css
│  ├─ common.css
│  ├─ layout.css
│  ├─ components.css
│  ├─ main.css
│  └─ pages.css
├─ js/
│  ├─ common.js
│  ├─ navigation.js
│  ├─ slider.js
│  └─ modal.js
└─ assets/
   ├─ images/
   └─ icons/
```

페이지 구성:

- 메인 페이지: `index.html`
- 소개 페이지: `pages/about.html`
- 서비스/메뉴 페이지: `pages/service.html`
- 후기/포트폴리오 페이지: `pages/review.html`
- 문의/오시는 길 페이지: `pages/contact.html`

## 6. 코드 작업 규칙

- HTML은 구조, CSS는 디자인, JS는 동작만 담당합니다.
- 클래스명은 kebab-case를 사용합니다.
- 의미 없는 클래스명을 사용하지 않습니다.
- 색상, 폰트, 여백, radius, shadow는 CSS 변수나 공통 클래스로 관리합니다.
- 레이아웃은 flex/grid를 우선 사용합니다.
- `position: absolute`와 `z-index`는 장식 요소나 꼭 필요한 경우에만 최소로 사용합니다.
- JS는 기능별 함수로 나누고, 요소가 없어도 에러가 나지 않게 작성합니다.
- 외부 라이브러리는 꼭 필요할 때만 사용합니다.
- SEO 기본 태그와 접근성 기본값을 유지합니다.

좋은 클래스명 예시:

```text
section-title
hero-content
feature-card
process-item
review-list
contact-form
primary-button
```

사용 금지 예시:

```text
box1
text2
item3
wrap01
div1
left-box
right-box
```

## 7. CSS 파일 역할

```text
reset.css        기본 초기화
common.css       변수, 폰트, body, container, 공통 유틸
layout.css       header, footer, section layout
components.css   button, card, badge, form, modal, slider
main.css         index.html 전용 스타일
pages.css        서브페이지 공통 스타일
```

CSS 작성 순서:

1. Reset
2. Design Token
3. Base
4. Layout
5. Component
6. Page
7. Responsive

동일한 스타일이 2회 이상 반복되면 공통 클래스 또는 컴포넌트로 이동합니다.

## 8. 반응형 기본 규칙

기본 분기점:

```text
desktop       1024px 이상
tablet        768px ~ 1023px
mobile        767px 이하
small mobile  480px 이하
```

반응형 필수 조건:

- 1440px, 1024px, 768px, 480px, 360px 화면에서 확인합니다.
- 모든 페이지는 360px 모바일 화면에서도 가로 스크롤이 없어야 합니다.
- 텍스트 잘림, 버튼 겹침, Hero 깨짐, 카드 깨짐이 없어야 합니다.
- 반응형을 단순히 width만 줄이는 방식으로 처리하지 않습니다.
- 레이아웃 구조 자체를 모바일에 맞게 재배치합니다.
- 모바일 반응형을 `transform: scale()`로 해결하지 않습니다.
- 2열/3열 카드는 모바일에서 1열 또는 2열로 자연스럽게 변경합니다.

Grid 기본 규칙:

```text
Desktop   3~4열
Tablet    2열
Mobile    1열
```

`body { overflow-x: hidden; }`은 가로 스크롤 원인을 해결한 뒤 최종 안전장치로만 사용합니다.

## 9. 이미지와 배경 규칙

- 모든 이미지는 `max-width: 100%; height: auto;`를 기본으로 합니다.
- 카드 이미지처럼 고정 비율이 필요한 경우 `aspect-ratio`를 사용합니다.
- 썸네일이나 카드 이미지는 `object-fit: cover`를 사용합니다.
- background-image 위에 텍스트를 올릴 경우 overlay 레이어를 사용합니다.
- 텍스트 박스에는 `max-width`를 지정합니다.
- 텍스트를 이미지 위에 `position: absolute`로 억지 배치하지 않습니다.
- Hero 텍스트는 화면 밖으로 밀리거나 잘리지 않아야 합니다.
- 모바일에서는 줄바꿈, 간격, 버튼 배치를 자연스럽게 조정합니다.
- 중요 피사체는 버튼이나 텍스트 뒤에 가려지지 않아야 합니다.

---

## 10. 접근성 기본 규칙

- 모든 의미 있는 이미지에는 alt를 작성합니다.
- 장식 이미지는 `alt=""`로 처리합니다.
- button에는 필요 시 aria-label을 작성합니다.
- label 없이 input을 사용하지 않습니다.
- color만으로 정보를 전달하지 않습니다.
- hover 상태만 있고 focus 상태가 없는 UI를 만들지 않습니다.
- 키보드 이동이 불가능한 메뉴나 모달을 만들지 않습니다.

---

## 11. 성능 기본 규칙

- 이미지는 가능한 lazy loading을 사용합니다.
- 불필요한 JS를 만들지 않습니다.
- 중복 CSS를 만들지 않습니다.
- 렌더링을 막는 스크립트를 최소화합니다.
- 애니메이션은 가볍게 사용합니다.
- 거대한 배경 이미지 남발을 피합니다.
- 사용하지 않는 CSS/JS를 남기지 않습니다.

---

## 12. 금지사항

- 기존 사이트와 동일한 컬러 팔레트, 카드 구조, 버튼 형태, Hero 구성을 반복하지 않습니다.
- Bootstrap, Tailwind UI, Flowbite, DaisyUI, StartBootstrap 같은 무료 템플릿처럼 보이는 일반적인 레이아웃을 피합니다.
- 글자를 배경 이미지 안에 absolute로 아무렇게나 배치하지 않습니다.
- Hero 텍스트에 큰 margin 값으로 위치를 맞추지 않습니다.
- `margin-top: 120px`, `padding-top: 300px` 같은 임시 보정값을 사용하지 않습니다.
- 카드 높이를 강제로 맞추려고 텍스트를 잘라내지 않습니다.
- line-height 1 이하를 사용하지 않습니다.
- 제목 전체에 font-weight 900을 사용하지 않습니다.
- 반응형 문제를 `transform: scale()`로 해결하지 않습니다.
- `!important`를 남발하지 않습니다.
- `z-index: 99999`를 사용하지 않습니다.
- inline style로 레이아웃을 해결하지 않습니다.
- 사용하지 않는 파일이나 중복 규칙 문서를 새로 만들지 않습니다.

## 13. 실패 기준

아래 중 하나라도 발생하면 실패입니다.

- 기존 화면이 깨짐
- 기존 동작이 사라짐
- 반응형이 무너짐
- 새 콘솔 에러가 생김
- 모바일에서 가로 스크롤이 생김
- 텍스트가 배경 영역 밖으로 밀림
- 버튼과 텍스트가 겹침
- 이미지 때문에 레이아웃이 깨짐
- 기존 프로젝트와 너무 비슷한 디자인이 반복됨
- AI가 만든 흔한 템플릿처럼 보임
